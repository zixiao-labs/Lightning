Lightning ⚡️

Nasti-native tests for Node.js, DOM emulators and real browsers.

English 中文 Compatibility / 兼容边界

Get started

Requires Node.js ≥22.12.0. The API alignment target is Vitest 5.0.3, not full Vitest/Jest feature parity.

pnpm add -D @lightning-js/lightning
pnpm exec lightning run
pnpm exec lightning watch
import { test, expect } from "@lightning-js/lightning";

test("adds", () => expect(1 + 2).toBe(3));
test.for([[1, 2, 3]] as const)("sum %i + %i", ([a, b, sum], { expect }) => {
  expect(a + b).toBe(sum);
});

Configure projects

import { defineConfig } from "@lightning-js/lightning/config";

export default defineConfig({
  test: {
    maxWorkers: 2,
    projects: [
      { test: { name: "unit", include: ["test/unit/**/*.test.ts"] } },
      "packages/*/lightning.config.ts",
    ],
  },
});

Use --project unit to filter. Inline, path/glob and nested projects inherit defaults; extends: false opts out. Reporters aggregate once across projects. Watch one project at a time.

Coverage, reports and type tests

pnpm exec lightning run --coverage --coverage-provider istanbul
pnpm exec lightning run --reporter junit --output-file artifacts/junit.xml
pnpm exec lightning run --shard 1/4
pnpm exec lightning run --typecheck

V8 reports source-mapped runtime ranges. Istanbul instruments original JS/TS/JSX ASTs. Both emit text/html/lcov/standard JSON and enforce thresholds. Declaration test files compile without execution, even under broad runtime globs.

Browser mode

pnpm add -D playwright
pnpm exec playwright install chromium
pnpm exec lightning run --browser
pnpm exec lightning watch --browser

Import DOM helpers from @lightning-js/lightning/browser. Always await userEvent: browser actions use trusted Playwright input; jsdom/happy-dom use a synthetic fallback. Browser V8 coverage requires Chromium; Istanbul does not depend on Chromium's coverage API.

Benchmarking

test("parse", async ({ bench, expect }) => {
  const result = await bench("JSON", () => JSON.parse("{}"), { time: 100 }).run();
  expect(result.throughput.mean).toBeGreaterThan(0);
});

// *.bench.ts / *.benchmark.ts
// lightning bench --baseline baseline.json
// lightning bench --compare baseline.json --regression-threshold 10

Context comparisons and measurements are serial. Legacy top-level bench and describe.bench remain supported. Benchmark regressions should be measured on controlled hardware.

pnpm add -D @lightning-js/lightning
pnpm exec lightning run

pnpm exec lightning run --typecheck
pnpm exec lightning bench

配置与迁移

  • 配置助手从 @lightning-js/lightning/config 导入， 支持 defineConfig 和 defineProject。
  • test.projects 支持内联、配置路径、目录、正 glob 与嵌套， 默认继承，使用 extends: false 关闭继承。
  • 使用 --project 选择项目；JSON/JUnit 在整个 run 结束时统一汇总。
  • Lightning 管线提供 Vitest/Jest 导入兼容；jest 是 vi 别名。Jest 配置仅映射明确的子集，不支持字段直接报错。
  • 使用 globals 时，编辑器类型来自 @lightning-js/lightning/globals。

运行时与验收

  • 支持选项式 test、for/条件 API、预期失败、结束/失败清理回调、 条件 Mock、异步断言与带取消信号的 poll。
  • Node 并发断言使用 async-local 状态；浏览器测试串行，避免 await 后状态串台。
  • V8 使用运行时 range 语义；Istanbul 提供原始 AST 插桩。 未执行文件零覆盖，阈值不达标或 reporter 失败均返回非零退出码。
  • 声明测试只编译、不执行；Tinybench 支持上下文 API、串行比较与 CLI 基线。
  • 浏览器 watch 只重跑依赖受影响的测试，运行期间的变化排队； 可信 click/hover 通过 Playwright 执行，交互必须 await。
  • 仓库内包含 Node、React/jsdom、Vue/happy-dom、浏览器、类型与基准样例。
