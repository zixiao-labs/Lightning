# Lightning v3.0.0

发布日期：2026-10-03。相比 `v2.2.0`，本次交付 Vitest **5.0.3 的兼容核心与选定新 API**，
重构运行时、覆盖率和报告，并完成路线图中的类型测试、基准测试与迁移工具链。
这是支持明确 API 子集的重大版本，**不宣称完整实现 Vitest/Jest**。

## Breaking changes / 升级注意事项

- **Node.js >=22.12.0**：不再支持 Node 20；CI 覆盖 Node 22 和 24。
- **浏览器交互必须 `await`**：`userEvent` 方法现在是异步操作，真实浏览器使用
  Playwright 可信输入；DOM 模拟环境使用合成事件回退。
- **异步断言必须 `await`**：遗漏等待的 `.resolves`、`.rejects`、`expect.poll`
  会使测试失败，不能再因断言未完成而得到假成功。
- **浏览器测试尝试串行执行**：浏览器缺少 async-local storage，以串行调度保证
  断言计数、soft failure、快照和异步断言的状态隔离；Node 仍支持并发测试。
- **覆盖率指标和 JSON 格式更新**：V8 provider 从旧的行级近似改为 source-map
  校验后的 V8-to-Istanbul range 语义；JSON 报告为标准 `coverage-final.json`。
  请重新评估旧阈值及读取旧 JSON 的脚本，不要直接比较新旧百分比。
  需要 AST 语句/分支插桩指标时使用 `istanbul`。
- **配置支持边界明确化**：导出配置对象或对象的 Promise，不支持配置工厂函数。
  项目 glob 仅支持正模式，`extends` 仅支持布尔值；不支持的 Jest 配置字段会明确报错。

升级：

```sh
# 先将 Node.js 升级到 >=22.12.0
pnpm add -D @lightning-js/lightning@3.0.0
pnpm exec lightning run
```

在浏览器模式或 DOM 环境中：

```ts
import { afterEach, expect, test } from "@lightning-js/lightning";
import { cleanup, render, userEvent } from "@lightning-js/lightning/browser";

afterEach(cleanup);

test("submits", async () => {
  const { container } = render("<button>Submit</button>");
  const button = container.querySelector("button")!;
  button.addEventListener("click", () => { button.textContent = "Done"; });
  await userEvent.click(button);
  await expect(Promise.resolve(button.textContent)).resolves.toBe("Done");
});
```

完整迁移说明：[Migration / 迁移指南](https://github.com/zixiao-labs/Lightning/blob/v3.0.0/docs/MIGRATION.md)。
旧测试签名、顶层 `projects`、`poolOptions.maxWorkers` 和顶层 `bench` API 继续保留。

## Highlights / 主要功能

### Vitest 5 API 与运行时

- 新增 `test(name, options, fn)`、`test.for` / `describe.for`、`skipIf` / `runIf`
  和 `test.fails`。
- 类型化测试上下文提供 `expect`、`task`、`onTestFinished`、`onTestFailed`；
  hook 可返回清理函数，失败后仍执行清理。
- `expect.poll` 回调接收 `{ signal }`，到期取消，悬挂回调不能无限等待。
- 新增 `vi.when(mock).calledWith(...)` 条件 Mock，支持返回值、Promise、抛错、
  有限次 action、disposal 和 `toHaveBeenExhausted`。
- 新增 `./config` 和 `./globals` 导出，以及 lazy `lightning()` 编程入口。

### 覆盖率、项目与 CI 报告

- V8 捕获实际求值代码，恢复并校验 Nasti 转换后的 source map，合并覆盖率范围；
  新增 Istanbul 原始 JS/TS/JSX 插桩 provider，支持 Node 和浏览器。
- 支持 include/exclude、未执行源文件零覆盖、lines/functions/branches/statements
  阈值，以及 text/html/lcov/json 标准报告；阈值和 reporter 错误产生非零退出码。
- `test.projects` 支持内联对象、配置文件、目录、正 glob、嵌套项目及默认继承；
  新增 `defineProject`、`test.maxWorkers` 和 `--project` 选择。
- 多项目报告按整次调用汇总，JSON 输出一个文档，JUnit 包含所有项目。
  支持 default/verbose/dot/json/junit/tap/github-actions 和自定义 reporter、
  `outputFile` 路径映射与 CI sharding。

### 浏览器、类型测试与基准

- 浏览器可信 click、真实 `:hover` 与异步交互；watch 按依赖重跑、使用新 page，
  并合并执行期间到达的变更，退出时清理资源。
- Chromium 支持 V8 覆盖率；浏览器支持 Istanbul 插桩。
- 新增 `expectTypeOf` / `assertType` 和 `--typecheck`；
  `*.test-d.ts` / `*.spec-d.ts` 只经 TypeScript 检查，绝不作为运行时测试执行，
  诊断保留文件、行、列和 TS 错误码。
- Tinybench 上下文 `bench`、串行比较、JSON 基线和吞吐回归门控。
  多项目共用一个根目录相对的基线，仅整次运行成功后写入。
- 提供 Vitest/Jest 导入兼容、配置发现、`jest === vi` 别名及 Jest 配置子集映射。
  导入改写限于 Lightning 模块管线，不修改整个 Node 进程的解析。
- 新增 React/jsdom、Vue/happy-dom、类型与基准示例，中英双语文档站，
  以及 Node 22/24、threads/forks 和 Chromium CI。

## Fixes / 正确性与技术债务修复

- Node 并发断言/快照状态按测试隔离，重试计数按尝试隔离；
  浏览器异步断言在 `await` 后仍保留测试作用域。
- globals 按文件安装并恢复原 descriptor，避免 inline/watch 宿主状态泄漏。
- runner deadline 使用原生时钟；worker 未报告结果便退出时不能产生假成功。
- 捕获文件生命周期内的未处理 rejection 和 uncaught exception，并归因到测试结果。
- `.only` 使用 AST 扫描，排除注释、字符串和普通测试体中的嵌套 collector 调用，
  修复全部测试被跳过却报告成功的问题。
- 项目 glob 跳过普通文件，仅接受目录或认可的配置文件；没有合法匹配时仍报错。
- 覆盖率在读取脚本/source map 前过滤到项目范围；缺失或损坏的 map
  不再让 collector 的 `stop()` 异常退出。
- scoped `expect` 不再代理 asymmetric matcher，保留字段和原生方法的正确语义。
- 类型测试复用 compiler host 和 SourceFile 缓存，同时保留每个入口的诊断归因。
- 断言与条件 Mock 共用无环 equality 模块；修复多项目基线覆盖、报告覆盖、
  无效 worker 数量和 reporter 错误带来的假成功。

## Known limitations / 明确未完成的事项

- 完整 Chai/Jest matcher、自动 module mocking 和 ESM live-binding 语义；
  `test.extend` fixtures、around hooks、tags/annotations。
- Vitest UI/trace/doctor、VM pools、文件系统 module cache；多项目同时 watch、
  类型测试 watch 和 WebdriverIO。
- Vitest 5 完整交错基准采样、专用比较 matcher、自定义 provider、from/writeResult。
- 任意用户 transform 链或 React compiler 输出的 V8 source-map 恢复。
  不匹配会明确失败，避免错误覆盖率；需要插桩级指标时使用 Istanbul。
- Firefox/WebKit 不支持 V8 coverage，请使用 Istanbul；本次真实浏览器验收为 Chromium，
  不把配置支持当作 Firefox/WebKit 实测结果。
- **武陵 DevOps 集成按项目决定延期**，等待武陵重构后的协议与鉴权约定；
  本版没有占位网络端点或凭据处理。
